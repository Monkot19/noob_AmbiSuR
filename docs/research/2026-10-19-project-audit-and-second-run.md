## 4. 二周目的主线：先回答一个能由实验否证的问题

用户已认可的 10-15 方向是：

> 原有 SH 选择可能遗漏可从现有 ALR 受益的对象；比较当前 Gaussian 平面与 DA3 候选平面的跨视角 NCC，补选其中一部分，再完整复用原标签渲染与 ALR，是否改善最终表面重建？

它与旧 N 是不同检验对象。不部署新 S×A 算式，不宣称校准了 SH 能量；A 保留官方双端标签，新增模块只从其未命中集合补充标签：

\[
b_i^{\mathrm{new}}=b_i^A\lor e_i.
\]

复用 AmbiSuR/PGSR 的相机、单应性 warp、NCC 和第5通道标签渲染。借鉴 Sparse2DGS 的双几何假设比较，首版保留 best-source 和 donor 决策起点；适配为 DA3 候选及标签输出，**不直接替换 Gaussian 位置**。同一 `b_new` 同时进入 renderer 与训练端掩码计算，仍使用原 ALR、DA3 confidence、调度和其它损失。

第一模块不加入特征网络、独占梯度归属门、梯度准入、两步模拟、QP、五状态或新生命周期。匹配无效时 `e=0`，保留基线标签与行为。它不是证明“所有高误差点都被发现”，而是检验一个限定的选择增量是否有用。

理论/源码/供体实验依据和具体接口以 `2026-10-15-source-faithful-research-route.md` 及来源 manifest 为准；本审计不重新设计算法，也不再扩大论文搜索作为启动前置。

两个后备独立实验仍保留：DP-GS 的可靠渲染锚点+DA3 法线深度传播；VCR 的 detached 法线一致性权重。它们都尚未移植。先分别检验相对 baseline 的增益，有用后才考虑联合；DP 还需“同掩码/同权重、目标为原 DA3 深度”对照，区分新目标与覆盖变化。梯度方法仅在后续真实问题需要时启用。

## 5. 如何真正开始，而不再耗在前置工程里

以下是建议的下一轮任务，不是本轮已执行工作，也不自动授权云端训练或恢复旧 GT 评价。

### 第一步：做一个短的二周目实施合同和版本检查点

利用已认可的 10-15 方向，明确它取代旧方案的哪些**待实现研究任务**，哪些数据/复用/安全规则继续有效。旧 approved design 与 AGENTS 中的 Core 阶段绑定需有显式适用范围增补，不能静默改变生产合同；不需要重新讨论已经认可的研究方向，更不需要把旧 C1–C6 先做完。

合同只闭合 selector 的输入/输出、抽样预算/独立 RNG、真实支持相机、标签生成时点、退化回基线、唯一开关和首次评价协议；未冻结的参数如实写出，不在正式结果后补选。将新路线、来源和本审计纳入一个文档检查点，并让后续交接只沿一个入口。不要补写所有历史实验的巨量逐项清单。

### 第二步：保留旧分支，在隔离分支实现最小接线

建议新建 `codex/second-run-selector`；起点可用当前 `62e9117` 以复用 seed/config/日志/接口，但旧 Core flags 全关，`c0-baseline` 保持参考锚点。这里是工程建议，不是已创建分支，也不宣称当前 HEAD 已有新的 G0 证据。

先做聚焦回归和 feature-off 检查；可在固定输入上比较关闭新模块前后的前向/梯度接口，沿用已有 G0 记录，不新增完整 baseline 训练或重新生成固定 output。若真实证据表明旧 D0 接线在关闭后仍改变行为，再基于干净基线代码做最薄接线；这是代码起点选择，不是重跑 baseline。不要先进行“清理整个 reliability 框架”的重构，也不整体搬运旧五状态依赖。

实现边界预计为一个 selector 模块、少量参数/调用及标签 override；精确文件以实施计划为准。新增标签必须在消费它的 render 之前准备，renderer/train 不能各算一版。关闭时沿原代码路径；避免为了新标签增加 CUDA 特征通道或重写 NCC。

### 第三步：用少量真实接口检查证明适配正确

测试针对新边界：合成相机/平面的投影约定；真实 NCC producer 的形状/有效索引；新增标签经过真实 renderer→`rendered_unc`→ALR consumer；`e=0` 与关闭路径回到基线。必须使用实际生产返回类型，不以预制字典或纯 NumPy 恒等式代替集成验证。

当前 bundled Python 实测为 3.12.14，NumPy 有、Torch/SciPy/Open3D 无。因此 CPU 数学检查与 Torch/CUDA 实际验证需区分；不得把旧服务器测试收据写成今天新模块通过。使用项目兼容环境做 CPU/静态检查，再在明确 commit 上做短步 GPU smoke。

**Smoke 必须覆盖实际启用后的迭代。** 默认 ALR 是严格 `iteration>7000`，单纯从0跑100–500轮无法验证新标签对 ALR 的接线。应选冻结可恢复起点后跑过该边界，或把明确标记的合成/短步资格测试用于活动路径；正式实验不偷偷改变启用时序。

顺带记录少量有解释力的量：A 未命中候选数、有效支持数、追加数、原/新标签渲染后的 ALR 有效权重质量、额外时间/显存。**Gaussian 数量增加不保证实际新增 ALR 监督增加**：遮挡或 DA3 confidence 可能使其贡献为零。这是诊断，不加入新的优化门。

### 第四步：第一组实验先打通“训练→mesh→几何评价”

先确认同一份数据/DA3、训练起点与预算、分辨率、mesh 提取参数和最终表面评价定义。现有中心到 GT 的 `>5cm` 标签是旧检测探针，不能代替表面重建的 accuracy/completeness、CD 或 F-score。DTU/TnT 使用已有各自协议；ScanNet++ 先明确单位、可评价域与采样/阈值，复用实际适用的既有工具，仅补必要薄适配。GT 只在获准的离线评价阶段出现。

baseline B 直接使用已有固定 output；本轮不新增 B 的训练或续训。新方法 B+selector 写入独立目录，优先对齐既有 baseline 的数据/DA3、配置、分辨率、训练预算及提取/评价方式。缺失 provenance 从既有日志、配置和凭据补核；无法确认的差异列为比较限制，不把不同运行条件下的差值宣称为严格配对因果增益，也不据此强制重跑基线。固定种子不保证 CUDA 位级确定，初始单 seed 差异不作最终结论。

已有 baseline mesh 和已有指标可复用时直接复用；若只缺评价数值，后续在获准的离线评价范围内从现有 mesh 生成独立评价记录，不重训、不覆盖 baseline output。当前先不依赖7k续训：本地 baseline 没有完整 checkpoint；即使以后找到，恢复规则仍须核实，不能将恢复缺口变成重跑基线的理由。

baseline 与 selector 有初步改善后，尽早做**扩大原 SH 选中比例**与**同数量随机补选**两个简单控制。随机补选的有效像素监督量仍需记录，不能只靠同点数宣布监督预算完全相等。若简单控制同样好，则复杂 NCC 选择的必要性尚未成立。

### 第五步：用结果决定扩大、诊断或停止

| 第一轮观察 | 后续动作 |
| --- | --- |
| 新模块没有产生有效新增监督 | 查标签、支持视角、坐标和 confidence 接线；先证明活动路径真正执行 |
| 工程/接口报错，NaN 或 feature-off 不等价 | 按系统调试修接口，保持科学配置；不以接口错误作科学负结果 |
| 接线正确、有效监督存在，但几何不改善 | 记录这组配置的负结果，查候选是否有区分能力/先验内容/优化响应；不无限调门槛 |
| selector 有收益但简单扩选同样好 | 尚不能主张 selector 更必要；重新评估选择机制成本 |
| selector 优于 baseline 和简单控制 | 再做 Tool/Utility 多 seed 与额外官方基准确认，报告成本和失败情形 |
| 独立 DP 或 VCR 实验也有稳定收益 | 做单项/联合对照，判断是否互补；不用预先要求数学上的超加性 |

单场景正结果不跳过 Utility/多 seed；旧 N 的 AUROC 门也不自动强加给新 selector，因为新 H1 的主要目标是最终重建效用，而非学习一个全域错误概率。新门须在实验前明确，不能通过事后换目标救结果。

## 6. 二周目应该改变的工作方式

第一轮主要失衡是：在动作效用尚未成立前，先建了较大状态/可靠性架构；然后用了大量诊断与流程工作试图为它找到充分理由。真实 producer/consumer 缺口又造成额外恢复成本。文献与公式推导有价值，但不能替代接线后的实际收益。

二周目应把第一里程碑改为：**一个默认关闭、可回退的 selector，完成真实标签/ALR 接线，并产出一组可复现的最终几何对照。** 为它补必要资格检查和清单，不以“通用框架完成”“五状态齐全”“再查几十篇论文”作为先决条件。接口正确而效用不成立时，允许停止这个模块；已有记录和负结果保留，切换到独立备选实验。

当前最需要开始的具体工作，是把已认可的 selector 路线收敛成短实施合同和一次最小实验方案；随后才进入隔离分支/TDD。旧 Utility 汇总恢复、Geometry Q、Supporting 和大规模跨场景框架均不阻塞这一步。
