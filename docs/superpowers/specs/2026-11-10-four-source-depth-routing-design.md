# 四来源深度选择：技术路线与首批离线规格

2026-11-10。**技术路线已获用户认可；本页首批数量、判据与接口是待审阅的具体提议，不是已实现或已授权启动的实验。** 主工作目录继续D盘。只写规格；本轮不安装、不推理、不读GT数值、不训练。

## 1. 已认可的路线与首个里程碑

固定照片对应 → 选择有位置分辨能力的支持 → 比较当前渲染／原DA3／spread／MVSAnywhere → 分区使用或削弱深度监督 → 检查实际渲染表面响应。

RoMa只提供观测对应，不把三角化深度加为第五个训练教师。三角化可保留为射线夹角／敏感度诊断。原NCC训练loss继续保留；替代的是候选深度判别证据。位置选择不限定于SH标签A未命中区域，不能把选中深度等同于需要额外ALR。

先做一批小型离线比较，直接回答：**从现有邻居列表增加可选支持后，四来源选择的误差、伤害和覆盖是否比原两支持改善？** 尚不同时实现分区loss或启动30K。

## 2. 现有代码与真实输入

- `scene/__init__.py:103–116`按距离为主排序，结合朝向／距离范围过滤，再截断邻居。朝向差不是同一点的三角化夹角，不能直接排序朝向差声称解决视差。
- 原生C0归档`multi_view.json`：DSC06348／DSC06274／DSC06289各8邻居，DSC06669有5，合计29配对。既有RoMa仅前2／每参考，共8对；**若复用原8对，只需新增21对**。列表是否真的提供更好的位置分辨能力尚未知。
- `utils/observed_correspondence.py::compare_candidates`已接收`N×4×S`代价，但只给MVS胜出；`build_correspondence_record`、match与score仍写死两个支持，不能直接宣称已实现四来源routing。
- 原4×16384像素、7K当前／DA3／spread／MVS数组与4份GT网格已有冻结产物。输入继续只读，不生成新来源、不重跑MVS、不改传播、不新渲染baseline。

## 3. 方案选择

| 路线 | 成本与限制 | 决定 |
|---|---|---|
| 只重排已匹配的前2支持 | 无新匹配，无法补充原本缺失的视差信息 | 仅保留作旧对照 |
| 扫描原列表全部候选，再按像素证据比较支持组合 | 29总配对／21新增，复用已有环境、权重和8对；列表可能仍无合适视角 | 首批提议 |
| 立即扩大到406视角／重新跑MVS／直接训练routing | 同时扩大来源、配对和执行，难定位改进原因 | 后置，不在首批 |

## 4. 首批数据与支持合同（提议）

1. 保留4个参考、原65536参考像素和四来源深度数组；RoMa版本、precise、坐标／分辨率／后端均沿用7c698a3已成功设置。原8对只读取原NPZ，新21对写新目录，旧partial／日志保留。
2. 新支持只读取原照片、相机内参与位姿，走既有COLMAP text/binary适配；不实例化训练Scene来改写数据或多视角列表，不要求新增支持的渲染深度。新配对的source_xy与循环／overlap证据沿用`query_matches`。
3. 同一点的射线夹角按真实匹配及固定相机计算，记录正深度／退化；不是用相机中心朝向夹角代替。图像级列表是候选池，支持有效性最终落实到像素。
4. 首批提议同时保存原前2对照与新组合：在原有forward有效、cycle<=1原生px、overlap>=0.5、正深度条件下，按有效射线夹角从大到小选最多2支持；按原列表索引破同分。这些条件尚是待验证的候选规则，不是正确性概率。低于2个有效支持时本条判为证据不足，原单支持只作描述。
5. 主结果不新增GT拟合的角度门槛；同时明确报告夹角、极线残差、±1px敏感度和支持残差。只选相对更大的角度不等于已经达到“足够视差”。若原池全部病态，不降低标准强行发布训练mask，回到用户讨论扩大支持池。
6. 支持组合由对应和相机先冻结，不能针对某个深度来源各挑最有利视角。四来源比较共用支持集合；无效投影不以删掉该来源的坏视角获得优势，记本条不可比较。明确记录缺失／越界，不能置零成本。

## 5. 四来源比较合同（离线，不是训练准入）

来源顺序保持`[current, DA3, MVS, spread]`，所有深度是同尺度、同相机camera-z。比较当前渲染而非高斯中心。每来源在同一支持集计算投影点到固定RoMa对应的像素距离，首批沿用算术平均，不叠加新confidence乘积或损失权重。

- DA3/current/MVS均有效时构成三来源合同；spread存在且有效则再作四来源合同。spread缺失不使三来源判别退出，两个域分别报告。
- 保存各来源代价、排序、最小／次小代价间隔、每支持是否同意胜者。唯一最小均值只称“离线候选胜者”；精确并列／无共同支持／来源无效均显式保留，不能将argmin直接输出为训练教师。
- 首批先评价连续间隔与多支持同意是否有区分力，不在看到GT后试多个margin挑最好结果。绝对残差／间隔／视差阈值及当前胜出后的削弱系数仍未批准；冻结成训练规则前须单独明确。没有证据的区域回退原DA3监督。
- 不将来源间相互一致当独立证据：spread锚点来自当前7K模型，MVS和匹配可能重复使用同一照片。改变支持组合是证据条件对照，不声称统计独立。

## 6. 评价和停止边界

沿用同一CLI与`paired_target_stats`、原GT网格／语义区域、原serializer，不建第二套evaluator或GT查询。所有配对、选择、代价和随机对照先冻结，GT只评价；失败记录保留，GT后失败不自动恢复重跑。

旧／新支持在相同可比域比较：最终所选目标相对DA3和当前的平均／中位收益、恶化>5mm比例、严重尾部、接受覆盖；另报各自原域覆盖，避免只丢困难像素造成虚假改善。原前2与新组合使用相同cycle／overlap／正深度条件和同一四来源排序，仅支持池／组合不同。原历史MVS-only结果另列，不能把改判别规则的差异归于支持变化。按来源、视角、原区域披露，保留天花板与小视差失败，不只报总体平均。

随机对照的具体提议：在每个参考／同一协议／三或四来源共同有效域内，对完整胜者标签向量作一次固定seed的随机置换，标签包含current／DA3／MVS／spread及abstain，保持各来源和abstain的GT前数量不变。共同域内所有参与来源均有效，因此不随机指派缺失spread；每像素只分配一个来源，不独立抽样造成重叠。其问题是“来源配额与接受规模不变时，证据是否把相应来源放在更合适的位置”。abstain在目标选择评价中回退DA3，current胜者用冻结current评估静态位置质量，不冒称其训练目标。保留原MVS-only随机合同供旧结果回读；不把两种随机对照混为同一估计。置换和产物在GT前冻结，GT后过滤数量另报，不声称完全等预算。

这4视角用于开发检验，不作为泛化完成证据。若首批有明确潜力，规则冻结后再讨论原17视角中的其他13个参考及其资源；它们也曾参加来源分析，不称独立验证集。当前不加13视角匹配或新GT查询。

只有来源选择证明有益后才讨论训练。离线目标收益不等于30K表面收益；来源差时不靠加大loss／预算掩盖。

## 7. 后续表面执行的接口边界（本批不实现）

| 路由证据 | 后续提议的动作 |
|---|---|
| 当前明确胜出 | 削弱外部绝对深度监督；不以当前深度自监督，不直接默认全部置零；系数待讨论 |
| DA3明确胜出 | 保留原DA3及原监督强度 |
| spread或MVS明确胜出 | 在确认域替换原绝对深度目标，首轮不额外提高权重、不与冲突DA3目标叠加 |
| 缺失、歧义或不可靠对应 | 原DA3与原置信门控回退 |

原`depth_weight`／全图mean／尺度归一化是未来最小对照的起点，不能对小掩码重新归一化而静默放大权重。原DA3置信度是否限制新目标、缓存是固定7K还是在线更新、mask更新时序等需要训练规格明确，本批不擅自决定。

`train.py`绝对depth目标与ALR原先验变量须分开命名／传递，不能更换深度教师时暗中更换ALR法线。原NCC、SH／ALR和renderer不由本批改变。若准确目标在训练中仍未带动表面，再独立讨论SPARF／CorresNeRF式渲染表面对应约束；错误对应不会被换loss形式自动修复。

## 9. 来源与结论边界

- COLMAP3.11.1实际`Model::GetMaxOverlappingImages`结合共享点和三角化角；`patch_match.h`分别提供角度／一致性过滤，支持“视差与对应有效性须共同考虑”，不保证本池能找到好支持。[源码](https://github.com/colmap/colmap/blob/3.11.1/src/colmap/mvs/model.cc#L105)。
- SPARF实际`corres_loss.py`将渲染深度投到固定照片对应，支持位置候选代价／未来表面执行的接口来源，不是本四来源选择器的已证明收益。[源码](https://github.com/google-research/sparf/blob/main/source/training/core/corres_loss.py#L68)。
- 本项目四视角结果已证明大基线存在有益目标、小视差与天花板仍失败；新支持选择、四来源routing及分区loss的效果均待检验。[原结果](../../research/2026-11-10-observed-correspondence-results.md)。

本页需用户审阅的是**第一批29对／仅新增21对、4原参考、离线支持选择与四来源排序**；后续13参考、训练判据、分区loss和30K不捆绑为自动授权。

独立只读builder check指出随机对照来源分配和旧／新支持归因需要明确，以上已补全；未发现其他重要接口歧义。该复核不等同代码实现或效果验证。
